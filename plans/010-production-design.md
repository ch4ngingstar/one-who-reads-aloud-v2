## The pipeline to build

Use one application, SQLite, and isolated inference workers. Retain the current FastAPI/Next.js interface, cache and FFmpeg assembly. This machine benefits from one owner of the GPU. Adding queues, agents talking to agents, or network services between every stage would add complexity without solving the listening problem.

| Stage | Contract and owner | Failure and revision behavior |
|---|---|---|
| 1. Import and segment | Deterministic import preserves paragraph boundaries, inline words, quoted speech, thought and system text. Each cue identifies chapter, source location, original text and text hash. Keep immutable source text. | Verify ordered word coverage against chapter input before saving. Where markup or chunk boundaries make classification uncertain, preserve the words and mark the cue. Existing books do not get reparsed automatically. |
| 2. Direct the scene | Director reads a contiguous scene with nearby action beats, recent speakers, POV and applicable aliases. Its output is indexed labels only: actor, addressee when supported, kind, optional short delivery note, and evidence cue IDs for non-obvious assignments. The format fixes the expected indices. | Deterministic explicit attributions outrank inferred ones. Keep the reported evidence inspectable. Retry a bad span with fewer targets and the same context. Mark ambiguous dialogue for review, without discarding correct neighbors. Manual assignments outrank subsequent automatic passes. |
| 3. Compile spoken copy | Source plus a line-specific reading override and project pronunciations produce exact spoken words. Stage directions and conditioning text are separate fields. Preview what will actually be spoken. | If the source itself says the wrong word, the reader can fix one line. A model never rewrites the chapter. Preserve edits across re-direction when the same cue can be matched unambiguously. Distinguish changing a spelling for one occurrence from changing pronunciation book-wide. |
| 4. Cast and record | Resolve canonical actor → approved reference/version → named renderer. Narrator stays on its approved route. Normal speech, private thought and whispered speech may have different directions while sharing actor identity. Give the actor a playable note such as “trying to sound casual in front of Effie.” Allow no note for ordinary speech. | Use an explicit capability mapping for each engine. For an engine that only supports inline tags, compile a short supported tag separately from spoken copy. Never speak context or instructions. Start with one output per source cue. Test joint exchanges later only if output can be aligned back to each cue. |
| 5. Review takes | Reject unusable audio, compare transcript with spoken copy, and confirm cast provenance. One default take; retry a failed take, or offer alternatives for a difficult principal line. Use a short context playback window for the listener. | ASR flags missing/repeated words. It cannot determine whether Nephis sounds like herself or whether a joke lands. Preserve the selected take. On worker failure resume the last incomplete cue. Never silently replace a character with the narrator. |
| 6. Mix and publish | Arrange approved takes in book order. Preserve pauses, whispers and timing for effects. Publish audio and its matching timed script as one identified edition. Keep the previous edition playable during revision. | Cache the exact speech inputs: words, actor/reference audio hash and transcript, engine/runtime revision, delivery settings, seed/take identity, and any preceding audio/text actually fed to that engine. Mix-level changes need only assembly. Verify a one-line edit rebuilds exactly the affected takes. |

**GPU policy.** Label first and unload the director. Group independent speech work by renderer, reusing a resident model. For a renderer that uses prior context, finish each dependent sequence in order. Reconstruct the chapter by cue ID, never completion order. Measure cold loads, time spent waiting, inference, retakes, verification and assembly. Reserve time for assembly based on measured runs. If a projected run exceeds 40 minutes, drop optional extra takes first; keep the chosen cast and show the overrun if necessary.
